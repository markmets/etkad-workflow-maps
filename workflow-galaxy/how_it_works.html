How the distances are calculated

Workflow Galaxy claims that some research workflows are more alike than others. This page says exactly what that claim rests on, in enough detail to disagree with it.

Everything reduces to one measurement, applied seven times. A workflow becomes a set of features; two workflows are compared by how much their sets overlap, weighted so that rare features count for more than common ones; and the seven results are averaged using whatever weights you set in the interface. There is no machine learning in the similarity, no embedding model, and nothing that has read the text for meaning. It is counting, carefully.

1. A workflow becomes seven bags of features

Each aspect turns a workflow into a plain set of strings. Nothing is invented: every feature is something the record actually states.

2. Rare features count for more

A feature shared by half the corpus is weak evidence; one shared by three workflows is strong. So every feature carries an inverse document frequency weight:

idf(f) = log(1 + N / (1 + dff))

where N = 240 workflows and df is how many of them carry the feature. In this corpus that produces:

A single shared rare method is worth roughly 2.3× a single shared common one — and that modest ratio is itself worth noticing. No method dominates this corpus. The commonest, Machine Learning, appears in only 32 of 240 workflows (13%), and only 11 methods reach 15. The 121 methods in play are spread thinly across the 186 workflows that declare any, so idf has far less work to do here than it would in a corpus where one or two terms were on everything. Weighting still matters for Subject and Wording, where the distributions are much steeper.

3. Overlap is measured as cosine similarity

Each workflow is now a sparse vector: one dimension per possible feature, holding that feature's idf weight if present and zero if not. Similarity is the cosine of the angle between two such vectors.

cos(A,B) = (A · B) / (‖A‖ × ‖B‖)

Cosine rather than Euclidean distance, because the division by both lengths makes the measure indifferent to how much a workflow declares. A thorough record with twenty methods and a terse one with six can still be judged similar if what they do declare agrees. That matters here: ETKAD workflows carry 8–20 methods because they are workflows, while most Marketplace entries are single-purpose and carry 1–3. Euclidean distance would separate them on verbosity alone.

Note that the shared features are squared in the dot product only because both vectors carry the same idf weight for a given feature — presence is binary, so Af × Bf = idf(f)² whenever both have it, and zero otherwise.

similarity = Σ wf · cosf(A,B)  ÷  Σ wf

At the default weights that gives 0.161, or 16%. Dividing by the total weight is what keeps the figure comparable when you turn an aspect off: without it, ignoring an aspect would shrink every similarity at once and the percentages would stop meaning anything.

This is why the sliders are the interface. There is no single correct weighting, and the atlas does not pretend to one. Two workflows that are 60% alike by software may be 5% alike by method. The honest answer to “are these similar?” is “in which respect?”

5. The Order of steps features

The other six aspects describe what a workflow contains. This one describes how it proceeds, and it is built to be blind to subject matter. For each workflow that tags at least three of its steps, two kinds of feature are emitted:

pos0:Capturethis kind of work appears in the first quarter of the run. Step positions are normalised to 0–1 first, so a 4-step workflow and a 20-step one are comparable.
Analysis>Enrichmenta step tagged Analysis is directly followed by one tagged Enrichment.

Two workflows about entirely different material score highly here if they capture early, analyse in the middle and disseminate late. 48 of 240 workflows have enough ordered tagging to get these features; the rest are drawn faded when this aspect is weighted, because they have no position in it.

6. Where the dots are placed is a separate question

Similarity is exact. Position is an approximation of it, and the two should not be confused.

The precomputed layouts reduce the weighted feature matrix to 60 dimensions with truncated SVD, then to two with UMAP (cosine metric, 8 neighbours, min_dist 0.18). The Custom layout is computed in the browser by stress majorisation on the blended distances, warm-started from the blended UMAP.

Read adjacency, never distance. UMAP preserves neighbourhoods, not distances. “These two dots touch” is trustworthy. “This cluster is twice as far from that one as from the third” is not — inter-cluster gaps are close to arbitrary and change between layouts. This is why the neighbour list in the detail panel is computed from the vectors directly and not from what is on screen.

7. Whether any of this is worth anything

A map can look convincing and know nothing, so the atlas carries a test it could fail. A fifth of each workflow's methods are hidden; its 5 nearest neighbours are found using one aspect on its own; the methods of those neighbours are pooled and checked against what was hidden. Two things fall out of that table. Order of steps knows nothing about subject, wording or software and still beats both — workflows that proceed the same way do the same things. Software lands below the baseline: you would do better ignoring which tools a project used than trusting them as evidence of similar work.

What this measurement cannot do

It compares records, not research. A method counts only if somebody wrote it down, so a workflow that plainly involved transcription but never said so is, to this calculation, a workflow without transcription. Roughly half the corpus — the Programming Historian lessons — has methods read out of its prose rather than declared by a person, which is weaker evidence again; the atlas marks which is which and can filter to declared only.

It has no idea what any project means. Two workflows using the same six methods on completely unrelated material will be judged near-identical, and sometimes that is exactly the useful finding, and sometimes it is a mirage. The neighbour list shows which features produced each match precisely so that you can tell the difference yourself.
